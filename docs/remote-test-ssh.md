# SSH submission and receipt lookup

`remote-test run` stages a clean, committed HEAD (including unpushed commits), saves the exact V1 job privately, and makes one SSH submission. It exits zero only after a matching `passed` terminal receipt is validated and published as a new private file. The local Ranger backend remains the default; this command does not promote remote results into an authoritative merge gate.

The operator-local SSH JSON contains `target` (SSH alias or user@host), `remoteCli` (absolute reviewed executable path), `remoteConfig` (absolute private executor configuration path), `executorId` (expected producer), and `profiles` (reviewed V1 profile manifests). Optional `timeoutSeconds` defaults to 660 (maximum 900); `receiptMaxAgeMs` defaults to one day. Files are operator-owned, without group/world write access, outside Git repositories. Profiles and their claimed digests must already be authenticated and approved by the operator, just as for the existing executor. The SSH peer must have the same approved profile and expected executor identity.

```text
bun src/cli.ts remote-test run --config <private-ssh-json> \
  --request <private-request-json> --worktree <clean-source-tree> \
  --staging-root <existing-private-directory> \
  --job-output <new-private-exact-job-json> --output <new-private-receipt-json>

bun src/cli.ts remote-test status --config <private-ssh-json> \
  --job <saved-exact-job-json> --output <new-private-receipt-json>
```

The request contains all V1 job fields except `commitDigest`, `treeDigest`, and `bundleDigest`. Those three bindings are derived from staging; supplying them is refused. Choose fresh job/correlation UUIDs, a current attempt generation, the located repository identity, approved profile/image/lock/platform bindings, and an absolute Unix millisecond deadline. The caller owns repository attribution, profile admission and attempt-generation authority. The command does not infer a repository identity from a remote URL. Staging roots must be private, operator-owned and outside Git; unsupported or dirty source fails before SSH. Existing output paths and competing output reservations refuse submission. The exact job is synced and atomically published with mode 0600 before transport. The temporary local bundle is removed after the attempt, while the saved job survives for lookup. A process crash may retain reservations/staging directories; inspect them before manual cleanup.

The reviewed remote executable must expose `ranger remote-test serve-stdio --config <private-executor-json>`. Pin a wrapper executable for a checked-out CLI if necessary; the wrapper must use a neutral working directory and disable source-selected Bun configuration and env files. The receiver validates one bounded JSON header followed by exact raw bundle bytes and EOF. It uploads into an exclusive private directory, verifies size and SHA-256 before calling the existing bounded durable executor, then removes only that upload. The remote jobs root must be mode 0700 and operator-owned. A `status` request has no body and only reads the exact private artifact directory. Missing evidence returns an explicit absent receipt; corrupt, mismatched, symlinked or nonprivate evidence refuses lookup. No endpoint, remote path, shell text, SSH flags or credentials come from a job.

Each SSH connection uses `BatchMode=yes`, `StrictHostKeyChecking=yes`, no PTY, no agent/port forwarding and no connection multiplexing. Keys and known hosts remain in operator SSH configuration; provision them separately. Command words come only from the operator configuration and are shell-quoted because SSH sends its command through the remote shell. This follows the [OpenSSH invocation contract](https://man.openbsd.org/ssh) and [client configuration documentation](https://man.openbsd.org/ssh_config). Bundle upload is capped at 64 MiB and held as a bounded verified local snapshot; the remote receiver streams it to a private file. Request headers and stdout responses are capped at 64 KiB. SSH diagnostics are drained but never included in public output. The SSH child inherits only local path/user/home/agent-socket variables, excluding Ranger, forge and bus credentials. The executable and SSH configuration are trusted operator state, not sandboxed code.

Nonzero SSH exits (including peer-command refusals), interrupted connections and absent receipts yield `pending` before the deadline or `infra_failed` after it. Nonzero exits are reported as `no_terminal_receipt`; they do not establish whether the peer admitted, refused or completed the job. A completed fixed receiver reports typed `invalid_receipt` or `receiver_failed` errors as structured JSON with transport exit zero; the client maps either to `infra_failed`, without treating them as test receipts. Corrupt or mismatched stored evidence therefore refuses lookup immediately through the real CLI, just as malformed, stale, future, wrong-producer or identity-mismatched receipt responses do. Private error details never enter the wire response. Validation binds every V1 identity field, including generation. All terminal test outcomes remain distinct. Transport exit zero alone is never success. Receipt publication failure exits nonzero; retrieve again into a new private output path. `status` never stages source, launches tests, or resubmits. Do not automatically rerun after connection loss: remote execution may still be active or may have completed without an exported receipt. Abort kills only the local SSH process group and does not prove remote cancellation. The remote CLI handles termination and has a 15-minute session limit; the executor retains its own bounded workload timeout. Automated fencing/recovery remains separate map work.

An authenticated peer and its expected producer bind provenance at this boundary; digest matching alone is not authentication. A caller must still check current HEAD, current admitted generation, platform applicability, review and CI before considering a remote result as gate evidence. Freshness compares receipt completion against the local clock and configurable maximum age; even a future timestamp is refused, so synchronize operator clocks. ARM64 success does not establish other-platform behavior.

Default tests use an injected SSH runner, a local fixed receiver and private temporary Git repositories; no live SSH or containers are needed. `RANGER_SSH_INTEGRATION_FIXTURE=<private-json> bun test test/remote-test-ssh-integration.test.ts` opts into an operator-prepared disposable SSH endpoint. The fixture is `{ "config": <SSH config>, "job": <fresh fully bound V1 job>, "bundlePath": <private staged bundle> }`; it submits once, expects a passed terminal receipt, and then checks receipt-only retrieval. Use a fresh job and future deadline on every invocation. No key, service, image, controller or host provisioning is performed. Live Clawbox execution and remote gate promotion remain unverified until the separate provisioning/pilot checkpoint.

The updated client uses SSH wire protocol V2; job and receipt identity contracts remain V1. V2 reports `receipt: null` with active/interrupted/busy state, or an immutable observed receipt with revoked state. Revoked success is never exported as accepted success. The receiver also accepts V1 requests and returns strict V1 responses without added state fields; an active, interrupted, busy or revoked outcome is represented as absent accepted evidence for those readers. New clients accept canonical V1 terminal replies, but require an upgraded receiver for V2 requests. Recovery and retry remain explicit operator actions. Rowless passed receipts are always reported as revoked historical observations; only an admitted, launched and committed ledger result can establish accepted success.

A V2 busy response means the requested job was not admitted. It consumes no attempt or terminal receipt; retry the identical request explicitly once the active slot is available. Generation advancement is independent of that slot: submitting a higher generation with the same repository and correlation ID durably supersedes older work even if the new request returns busy. The running executor observes this fence and aborts the older attempt as cancelled. Use a distinct correlation ID for independent work; repeat the same superseding job after the older attempt exits or explicit recovery clears its slot.
