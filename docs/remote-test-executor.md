# One-shot remote-test execution

`bun src/cli.ts remote-test execute --config <operator-json> --job <admitted-job-json> --bundle <source.bundle> --output <new-private-receipt-json>` runs one reviewed profile. Only a passed receipt exits zero. The local Ranger test backend remains the default; this command does not promote a receipt into a merge gate.

The private operator config is `{ "executorId": "executor-name", "jobsRoot": "/absolute/private/jobs", "profiles": [{ "profile": <V1 manifest>, "lockFile": "bun.lock", "imageReference": "registry.example/runtime@sha256:<digest>" }] }`. The image reference must match the manifest image digest. Configuration and receipts must be outside Git repositories, configuration must be operator-owned without group/world write access, and a private output reservation directory refuses competing CLI calls before execution. Complete synced JSON is then published exclusively with mode 0600. Jobs root must already exist, be operator-owned, and not be group/world writable. Treat it as a single service's exclusive workspace; never concurrently modify its contents.

The operator owns profile approval, provenance and digest authentication and supplies the already admitted job. The job can select an approved profile by name but cannot supply commands, environment, container flags or resource overrides. Execution revalidates the V1 bindings, expiry, bundle bytes, detached commit/tree, and committed lock bytes. The supplied image is inspected locally at its manifest digest; it is never pulled. It must be a reviewed Linux ARM64 Bun runtime with the dependencies needed for offline commands. Tests have no network; dependency installation or caching is outside this slice.

Execution requires local rootless Podman on Linux ARM64 with cgroup v2 CPU, memory and PID controllers. A private exclusive lane refuses concurrent jobs. The container has a non-root UID/GID, private namespaces, no network, dropped capabilities, no new privileges, a read-only image, one job-checkout bind and bounded temporary storage. Image volumes, inherited environment, proxy forwarding and health checks are disabled. Unexpected configured mounts refuse startup. The wrapper starts in neutral temporary storage with an empty explicit Bun config and automatic env-file loading disabled, then checks cgroup CPU/memory/swap/PID files before starting profile children in `/work`. The runtime image must support these Bun CLI flags. Limits are two CPUs, 1.5 GiB aggregate memory with zero swap, 256 PIDs and at most ten minutes or the request deadline, whichever is earlier. Processes and sidecars within the container share those limits. Wall-clock expiry uses the supervisor timer and Podman's conmon timeout, which remains active if the supervising process disappears.

The fixed Bun wrapper emits the terminal JSON; profile commands run in order with stdout/stderr drained into a bounded combined private log. A nonzero test exit is `test_failed`, OOM or incomplete engine output is `infra_failed`, and supervisor timeout/cancellation kills the container and its engine process group. All terminal paths attempt forced container removal and workspace teardown. Network `none` creates no external job network. Failed cleanup or uncertain creation without a recoverable cidfile yields `infra_failed` and retains the lane/source for operator inspection, preventing reuse beside a possibly surviving job. This includes engine flag rejection during creation: absence of a cidfile cannot prove there is no allocation. Do not remove a retained lane until verifying that the owned container is gone. CLI errors remove the reservation; the output file never contains partial receipt JSON.

Deterministic regression tests inject the engine launcher and restore real temporary Git bundles; bootstrap tests execute the Bun wrapper against temporary controller-file fixtures. These prove policy construction and check behavior, not live kernel resource enforcement. `RANGER_EXECUTOR_INTEGRATION_IMAGE=<already-provisioned-name@sha256:digest> bun test test/remote-test-executor-integration.test.ts` explicitly opts into disposable-container tests on an operator-prepared Linux ARM64 host. It demonstrates reported controller files, outcomes and teardown; it does not stress resource enforcement. The fixture requires no live journal, bus or credentials and does not provision a host. Actual host enforcement remains unverified; the separate private provisioning/pilot checkpoint must demonstrate CPU throttling, aggregate OOM behavior, PID exhaustion, deadline termination, network isolation and the absence of host credential/config mounts, alongside the capacity baseline, before deployment or authority promotion.

Runtime flag semantics follow the [Podman create documentation](https://docs.podman.io/en/latest/markdown/podman-create.1.html), including conmon timeout, private networking, resource limits and non-root user mapping.

Only `/tmp` has a storage size bound in this slice. The writable checkout uses the operator's jobs filesystem without a disk quota; capacity and disk-exhaustion policy must be assessed privately before live deployment. Invalid input, unapproved profile or unsafe operator configuration can throw without a receipt; operational refusals of a validated identity return `rejected`. CLI errors remove their reservation directory. Busy or retained lanes currently return `rejected`, which is refusal of execution rather than a test verdict.

## Durable receipts and private logs

Every terminal executor result is stored under `jobsRoot/.artifacts/<validated-job-UUID>/`. The directory and store use mode 0700; `receipt.json` and captured `test.log` use mode 0600. The V1 receipt retains the full admitted identity tuple and observed status/exit code, and adds execution start/duration, resource observation state, and retained-log bytes/SHA-256/truncation metadata. The wrapper reports cgroup CPU microseconds and peak memory where available. Missing resource measurements are explicitly `unavailable`; resource observations use `skipped` when profile commands never started. Capture of the attached stderr stream, including engine/bootstrap diagnostics, is independent: a launched bootstrap can have a captured empty log while command resource observations are skipped. Older V1 receipts remain readable, but this executor always stores the evidence fields. Earlier strict V1 readers must be upgraded before using this executor; the remote lane is not deployed or promoted in this slice. Log checksums establish byte integrity, not producer authentication or merge authority.

Optional operator `artifacts` configuration accepts `retentionMs`, `maxArtifactBytes` and `maxLogBytes`. Defaults are seven days, 10 GiB aggregate receipt/log bytes and 1 MiB retained log bytes per job (maximum configurable log size: 64 MiB). Capture drains excess output and marks truncation. Logs are never printed or published by Ranger.

Publication syncs complete files and their private temporary directory, renames that directory atomically, then syncs the store directory before returning success. Unsupported durability operations or storage failure throw without returning passed. CLI output uses a separate atomic exclusive export after durable storage; export failure exits nonzero. Job IDs with retained terminal receipts cannot overwrite those receipts. This bounded store is not a permanent deduplication ledger: expiry removes the replay guard. Admission owns attempt fencing; new attempts should use new job IDs and the appropriate generation.

Publication holds a private store lock while enforcing age and aggregate limits. Expired terminal receipts of every status are removed; capacity pressure preserves unexpired evidence and rejects new storage writes. Pending/unknown entries count against capacity but are never reclaimed automatically. Active execution workspaces live outside this store and are never traversed by retention. A single result larger than the cap, capacity exhausted by retained or pending/unknown entries, malformed existing receipts, or a busy/stale store lock fails visibly. Locks and abandoned temporary directories left by abrupt process death require operator inspection; do not delete pending/unknown state to force storage space. Age cleanup is independent of the incoming write and can remove expired evidence even if that write fails. Cleanup runs on publication, so an idle store can retain expired evidence until the next result, while successfully stored evidence remains capped.

Storage capacity and lock checks run at terminal-result publication, after container/source cleanup; they do not reserve artifact capacity or gate execution admission. A full store, stale lock or failed storage operation can therefore leave a completed execution without a receipt: the executor throws, the CLI exits nonzero with no receipt export, and success is never exposed. A successfully cleaned executor lane is released even when storage later fails. Operators must resolve private storage failures before retrying; recovery/admission policy is separate work.
