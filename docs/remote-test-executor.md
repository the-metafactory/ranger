# One-shot remote-test execution

`bun src/cli.ts remote-test execute --config <operator-json> --job <admitted-job-json> --bundle <source.bundle> --output <new-private-receipt-json>` runs one reviewed profile. Only a passed receipt exits zero. The local Ranger test backend remains the default; this command does not promote a receipt into a merge gate.

The private operator config is `{ "executorId": "executor-name", "jobsRoot": "/absolute/private/jobs", "profiles": [{ "profile": <V1 manifest>, "lockFile": "bun.lock", "imageReference": "registry.example/runtime@sha256:<digest>" }] }`. The image reference must match the manifest image digest. Configuration and receipts must be outside Git repositories, configuration must be operator-owned without group/world write access, and output is exclusively reserved with mode 0600 before execution. Jobs root must already exist, be operator-owned, and not be group/world writable. Treat it as a single service's exclusive workspace; never concurrently modify its contents.

The operator owns profile approval, provenance and digest authentication and supplies the already admitted job. The job can select an approved profile by name but cannot supply commands, environment, container flags or resource overrides. Execution revalidates the V1 bindings, expiry, bundle bytes, detached commit/tree, and committed lock bytes. The supplied image is inspected locally at its manifest digest; it is never pulled. It must be a reviewed Linux ARM64 Bun runtime with the dependencies needed for offline commands. Tests have no network; dependency installation or caching is outside this slice.

Execution requires local rootless Podman on Linux ARM64 with cgroup v2 CPU, memory and PID controllers. A private exclusive lane refuses concurrent jobs. The container has a non-root UID/GID, private namespaces, no network, dropped capabilities, no new privileges, a read-only image, one job-checkout bind and bounded temporary storage. Image volumes, inherited environment, proxy forwarding and health checks are disabled. Unexpected configured mounts refuse startup. The wrapper verifies actual cgroup CPU/memory/swap/PID files before any profile command. Limits are two CPUs, 1.5 GiB aggregate memory with zero swap, 256 PIDs and at most ten minutes or the request deadline, whichever is earlier. Processes and sidecars within the container share those limits. Podman's conmon timeout remains active if the supervising process disappears.

Only the fixed Bun wrapper emits the terminal JSON; profile commands run in order with discarded output. A nonzero test exit is `test_failed`, OOM or incomplete engine output is `infra_failed`, and supervisor timeout/cancellation kills the container and its engine process group. All terminal paths attempt forced container removal and workspace teardown. Network `none` creates no external job network. Failed cleanup yields `infra_failed` and retains the lane/source for operator inspection, preventing reuse beside a possibly surviving job. Do not remove a retained lane until verifying that the owned container is gone.

Deterministic regression tests inject the engine launcher and restore real temporary Git bundles. `RANGER_EXECUTOR_INTEGRATION_IMAGE=<already-provisioned-name@sha256:digest> bun test test/remote-test-executor-integration.test.ts` explicitly opts into disposable-container tests on an operator-prepared Linux ARM64 host. The fixture requires no live journal, bus or credentials and does not provision a host. A private capacity baseline and provisioning/pilot checkpoint are still required before deployment or authority promotion.

Runtime flag semantics follow the [Podman create documentation](https://docs.podman.io/en/latest/markdown/podman-create.1.html), including conmon timeout, private networking, resource limits and non-root user mapping.
