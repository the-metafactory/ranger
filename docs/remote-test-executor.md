# One-shot remote-test execution

`bun src/cli.ts remote-test execute --config <operator-json> --job <admitted-job-json> --bundle <source.bundle> --output <new-private-receipt-json>` runs one reviewed profile. Only a passed receipt exits zero. The local Ranger test backend remains the default; this command does not promote a receipt into a merge gate.

The private operator config is `{ "executorId": "executor-name", "jobsRoot": "/absolute/private/jobs", "profiles": [{ "profile": <V1 manifest>, "lockFile": "bun.lock", "imageReference": "registry.example/runtime@sha256:<digest>" }] }`. The image reference must match the manifest image digest. Configuration and receipts must be outside Git repositories, configuration must be operator-owned without group/world write access, and a private output reservation directory refuses competing CLI calls before execution. Complete synced JSON is then published exclusively with mode 0600. Jobs root must already exist, be operator-owned, and not be group/world writable. Treat it as a single service's exclusive workspace; never concurrently modify its contents.

The operator owns profile approval, provenance and digest authentication and supplies the already admitted job. The job can select an approved profile by name but cannot supply commands, environment, container flags or resource overrides. Execution revalidates the V1 bindings, expiry, bundle bytes, detached commit/tree, and committed lock bytes. The supplied image is inspected locally at its manifest digest; it is never pulled. It must be a reviewed Linux ARM64 Bun runtime with the dependencies needed for offline commands. Legacy profiles have no network. Optional [reviewed profiles](remote-test-profiles.md) additionally bind named commands, frozen offline dependency installation and a pinned job-private NATS sidecar into their manifest digest.

Execution requires local rootless Podman on Linux ARM64 with cgroup v2 CPU, memory and PID controllers. A private exclusive lane refuses concurrent jobs. The container has a non-root UID/GID, private namespaces, no network, dropped capabilities, no new privileges, a read-only image, one job-checkout bind and bounded temporary storage. Image volumes, inherited environment, proxy forwarding and health checks are disabled. Unexpected configured mounts refuse startup. The wrapper starts in neutral temporary storage with an empty explicit Bun config and automatic env-file loading disabled, then checks cgroup CPU/memory/swap/PID files before starting profile children in `/work`. The runtime image must support these Bun CLI flags. Limits are two CPUs, 1.5 GiB aggregate memory with zero swap, 256 PIDs and at most ten minutes or the request deadline, whichever is earlier. Processes and sidecars within the container share those limits. Wall-clock expiry uses the supervisor timer and Podman's conmon timeout, which remains active if the supervising process disappears.

The fixed Bun wrapper emits the terminal JSON; profile commands run in order with stdout/stderr drained into a bounded combined private log. A nonzero test exit is `test_failed`, OOM or incomplete engine output is `infra_failed`, and supervisor timeout/cancellation kills the container and its engine process group. All terminal paths attempt forced container removal and workspace teardown. Network `none` creates no external job network. Failed cleanup or uncertain creation without a recoverable cidfile yields `infra_failed` and retains the lane/source for operator inspection, preventing reuse beside a possibly surviving job. This includes engine flag rejection during creation: absence of a cidfile cannot prove there is no allocation. Do not remove a retained lane until verifying that the owned container is gone. CLI errors remove the reservation; the output file never contains partial receipt JSON.

Deterministic regression tests inject the engine launcher and restore real temporary Git bundles; bootstrap tests execute the Bun wrapper against temporary controller-file fixtures. These prove policy construction and check behavior, not live kernel resource enforcement. `RANGER_EXECUTOR_INTEGRATION_IMAGE=<already-provisioned-name@sha256:digest> bun test test/remote-test-executor-integration.test.ts` explicitly opts into disposable-container tests on an operator-prepared Linux ARM64 host. It demonstrates reported controller files, outcomes and teardown; it does not stress resource enforcement. The fixture requires no live journal, bus or credentials and does not provision a host. Actual host enforcement remains unverified; the separate private provisioning/pilot checkpoint must demonstrate CPU throttling, aggregate OOM behavior, PID exhaustion, deadline termination, network isolation and the absence of host credential/config mounts, alongside the capacity baseline, before deployment or authority promotion.

Runtime flag semantics follow the [Podman create documentation](https://docs.podman.io/en/latest/markdown/podman-create.1.html), including conmon timeout, private networking, resource limits and non-root user mapping.

Only `/tmp` has a storage size bound in this slice. The writable checkout uses the operator's jobs filesystem without a disk quota; capacity and disk-exhaustion policy must be assessed privately before live deployment. Invalid input, unapproved profile or unsafe operator configuration can throw without a receipt; operational refusals of a validated identity return `rejected`. CLI errors remove their reservation directory. Busy executors report an unadmitted request without consuming its identity; retry the identical request explicitly after the current attempt completes or recovery clears it. An unexpected retained lane interrupts the admitted attempt and raises the durable recovery fence. Expiry before launch returns `timed_out` as an admission refusal; it does not establish that tests ran.

## Durable receipts and private logs

Every terminal executor result is stored under `jobsRoot/.artifacts/<validated-job-UUID>/`. The directory and store use mode 0700; `receipt.json` and captured `test.log` use mode 0600. The V1 receipt retains the full admitted identity tuple and observed status/exit code, and adds execution start/duration, resource observation state, and retained-log bytes/SHA-256/truncation metadata. The wrapper reports cgroup CPU microseconds and peak memory where available. Missing resource measurements are explicitly `unavailable`; resource observations use `skipped` when profile commands never started. Capture of the attached stderr stream, including engine/bootstrap diagnostics, is independent: a launched bootstrap can have a captured empty log while command resource observations are skipped. Older V1 receipts remain readable, but this executor always stores the evidence fields. Earlier strict V1 readers must be upgraded before using this executor; the remote lane is not deployed or promoted in this slice. Log checksums establish byte integrity, not producer authentication or merge authority.

Optional operator `artifacts` configuration accepts `retentionMs`, `maxArtifactBytes` and `maxLogBytes`. Defaults are seven days, 10 GiB aggregate receipt/log bytes and 1 MiB retained log bytes per job (maximum configurable log size: 64 MiB). Capture drains excess output and marks truncation. Logs are never printed or published by Ranger.

Publication syncs complete files and their private temporary directory, renames that directory atomically, then syncs the store directory before returning success. Unsupported durability operations or storage failure throw without returning passed. CLI output uses a separate atomic exclusive export after durable storage; export failure exits nonzero. Job IDs with retained terminal artifacts cannot overwrite those artifacts. The separate execution ledger retains identity and terminal receipts after artifact retention, so removing old logs does not permit execution replay.

Publication holds a private store lock while enforcing age and aggregate limits. Expired artifact receipts of every status are removed; capacity pressure preserves unexpired evidence and rejects new storage writes. Pending/unknown entries count against capacity but are never reclaimed automatically. Active execution workspaces live outside this store and are never traversed by retention. A single result larger than the cap, capacity exhausted by retained or pending/unknown entries, malformed existing receipts, or a busy/stale store lock fails visibly. Locks and abandoned temporary directories left by abrupt process death require operator inspection; do not delete pending/unknown state to force storage space. Age cleanup is independent of the incoming write and can remove expired evidence even if that write fails. Cleanup runs on publication, so an idle store can retain expired evidence until the next result, while successfully stored evidence remains capped.

Storage capacity and lock checks run at terminal-result publication, after container/source cleanup; they do not reserve artifact capacity or gate execution admission. A full store, stale lock or failed storage operation can therefore leave a completed execution without a receipt: the executor throws, the CLI exits nonzero with no receipt export, and success is never exposed. A successfully cleaned executor lane is released even when storage later fails. Operators must resolve private storage failures before retrying; recovery/admission policy is separate work.

If CLI output export fails after successful durable storage, the error identifies that boundary and leaves the existing output untouched. Repeat `execute` with the identical job and a new output path, or use SSH `status`: both retrieve the ledger's currently fenced terminal receipt without rerunning tests. Loose artifact bytes alone must not be exported as accepted success because cancellation may have occurred after their publication.

## Job admission and restart recovery

Execution opens only `jobsRoot/.execution/ledger.sqlite`, an operator-owned mode-0600 SQLite database in a mode-0700 directory outside Git repositories. Symlinked or hardlinked database files and unsafe directories refuse. This schema is independent of Ranger's supervisor journal; no supervisor store module or migration is loaded. SQLite IMMEDIATE transactions with FULL synchronous rollback-journal commits serialize admission across processes. The ledger is durable identity/fencing state, not a bounded log store; do not delete it to reclaim artifact space. Its growth must be included in private deployment capacity planning. The database declares schema version 1 with SQLite user_version; unknown versions and nonempty unversioned databases refuse without migration.

The same job UUID and typed identity tuple admits one attempt. An active duplicate reports active status; an identical terminal duplicate preserves the ledger-committed observed outcome. Revoked committed success is reported separately and cannot be exported as accepted success; committed test failures stay test failures. Before terminal ledger commit, expiry or cancellation instead produces a refusal, even if container output or an artifact already exists; that uncommitted artifact remains historical evidence. Reusing a UUID with another tuple refuses before any mutation. Generations are scoped by `(repositoryId, correlationId)`: use the same correlation ID for successive generations of one verification request, a new job UUID per generation, and a higher generation to supersede older work. Even a busy request durably advances the highest generation in its scope, fencing older work while leaving its own job identity unadmitted. Admission remembers the highest generation; cancellation revokes that entire generation, including jobs not yet admitted. A distinct request needs a distinct correlation ID.

The ledger reserves one active admission slot across processes. Abrupt process death leaves that slot occupied until explicit reconciliation, even if no recovery command has yet set the global fence. Other job identities remain unadmitted rather than becoming terminal rejections. Each attempt has a fresh private token. The executor checks it immediately before container create and start, polls durable fences while running, and binds it to container labels and the lane owner file. `remote-test cancel --config <operator-json> --job <exact-job-json>` records cancellation durably; a live executor observes the fence and aborts. Signal cancellation uses the same durable record. Expired, cancelled or superseded work cannot pass the launch check or commit an accepted success. Artifact publication precedes the fenced terminal ledger commit; an interruption between them is uncertain, not successful. SSH lookup checks the fence again after file I/O and refuses corrupt retained artifacts. A completed passed receipt remains immutable when later cancelled or superseded; the ledger marks its eligibility revoked. Direct execute refuses that success, and SSH V2 reports the original observed receipt with revoked state. Only currently eligible ledger results can be exported as accepted success. This still does not promote remote results into Ranger gates.

After the former executor has stopped, run `remote-test recover --config <operator-json> --executor-stopped`. The flag asserts the operator's precondition; it does not stop a service or prove process absence. Recovery durably fences admission and old attempt tokens before inventory, inspects only containers carrying this ledger's label, forcibly removes them, and inventories again to confirm absence. Unknown or malformed ownership fails closed. Only then does it remove known job workspaces and an owned lane. Thrown execution/storage attempts are durably marked interrupted and fence admission until recovery; they are never reported as a live owner. Interrupted attempts never recover success from container exit codes or loose artifact receipts. A validated private rowless receipt can be retained only when there is no recorded attempt; this preserves replay protection after artifact retention without halting admission. Its zero-attempt provenance can never establish accepted success: a passed observation remains revoked because a genuine pre-ledger artifact cannot be distinguished from one left after a ledger reset that lost cancellation. Historical failures retain their observed status. Never delete or reset the ledger to reclaim storage. An interrupted first attempt can admit at most one fresh infrastructure retry of the same immutable job; another interruption becomes terminal `infra_failed`. Test failures and other terminal outcomes never retry. If an interrupted publication already left an artifact, retry admission consumes the remaining allowance, but execution refuses to overwrite the artifact and marks that retry interrupted, fencing admission. The next recovery exhausts the two-attempt limit and commits infra_failed. The historical artifact stays unchanged and cannot be adopted as accepted success for that recorded attempt.

Failed recovery leaves the durable admission fence set. Retry recovery after resolving the failure. An abrupt death during recovery may leave `.execution/recovery-lock`; verify that no recovery process remains before operator removal. Legacy lanes without an attributable owner file require operator inspection. Recovery requires exclusive ownership of this jobs root and absence of any unlabelled legacy remote-test containers; it cannot identify or stop containers that predate these labels. This slice provides code and offline injected-engine tests, not host provisioning, restart-service installation, or live enforcement evidence.
